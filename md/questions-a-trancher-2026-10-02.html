⚙️ code

Qui tranche : 👥 Groupe, puis Jeff (Q-JEF-19)

🧑‍💼 Se tranche avec Jeff : Q-JEF-19, dans le rapport Jeff.

  • La base excluait la borne : '[)' ; passée en '[]' le 2026-10-05 (01:710).
  • Le code l'inclut : prix <= montant_max (rem.py:241).
  • Le sujet se contredit : « < 200 000 € » (RCR:173) contre BETWEEN (RCR:188).
  • ❌ Risque : un prix de 199 999,50 € sans tranche, ou deux tranches pour 200 000 €.
  • La contradiction, mot pour mot (REGLES-CALCUL-REMUNERATION.md) :
  • • l. 173-174, le tableau : « < 200 000 € » → 30 %, puis « 200 000 – 349 999 € » → 35 %. Les bornes sont en euros entiers.
  • • l. 188, la requête : « AND :prix BETWEEN montant_min AND COALESCE(montant_max, 999999999) ». BETWEEN inclut les deux bouts.
  • • l. 181 : « à 349 999 € le taux est de 35 %, à 350 000 € il passe à 40 % ».
  • ➡️ Un prix a des centimes (NUMERIC(12,2)). Avec montant_max = 349 999, un prix de 349 999,50 € ne tombe dans aucune tranche. Avec montant_max = 350 000, 350 000 € tombe dans deux tranches : la requête en prend une au hasard.

🗣️ En clair

  • Le barème dit : « en dessous de 200 000 €, 30 % ; à partir de 200 000 €, 35 % ». Il faut savoir dans quelle case tombe pile 200 000 €, et 199 999,50 €.
  • La base répond « case du dessus », le code répond « case du dessous ». Les deux ne peuvent pas avoir raison en même temps.
  • Le sujet lui-même hésite (citations ci-dessous) : c'est à nous de fixer la règle, puis de la faire valider par Jeff.

  • ➡️ Tranches [0 ; 199 999], [200 000 ; 349 999]… : ni trou, ni chevauchement. La base, le code (prix <= montant_max, rem.py:241) et le tableau du sujet (l. 173-174) disent la même chose.
