✅ Q-REM-03 · Figer le score de performance sur le paiement ?

🗄️ change la BDD

Qui tranche : 👥 Groupe

🧑‍💼 Se tranche avec Jeff : Q-JEF-20, dans le rapport Jeff.

  • F10:275-287 exige de figer les éléments du calcul.
  • Le sujet liste score_performance dans les paiements (RCR:286).
  • payment fige les taux, pas le score.

🗣️ En clair

  • Le score est une note sur 100 du chasseur pour cette vente. Il mélange 5 critères : délai, exclusivité, ventes, mandats, visites (rem.py:219-228).
  • Le taux est un pourcentage des honoraires que touche le chasseur. Il part du barème (30 à 50 %), puis bouge avec l'ancienneté et la performance (rem.py:259-265).
  • Le lien entre les deux : le score devient un « bonus performance » de −20 % à +20 % (rem.py:255-256). Score 50 → 0 %, score 100 → +20 %, score 0 → −20 %.
  • Exemple : tranche à 40 %, score 75 → bonus +10 % → taux 40 % × 1,10 = 44 %.
  • La base garde le bonus (performance_rate), pas la note. On peut retrouver la note depuis le bonus… tant que le pivot (50) et l'amplitude (20 %) ne changent jamais. S'ils changent, la note d'hier est perdue.
  • ✅ Réponse du 2026-10-02 : colonne
  • 📝 Commentaire : « à documenter et à confirmer avec Jeff »
  • ➡️ Conséquence : colonne payment.performance_score, à documenter dans l'ADR. Confirmation de Jeff : Q-JEF-20.
