En deux mots : les notions du chantier

🏠 Le schéma, c'est le plan de la maison. Les tables sont les pièces ; les contraintes sont les règles du lieu (« pas plus de six personnes dans le salon »).

Il y a deux façons d'avoir une maison au nouveau plan :

  • 🆕 construire neuf sur le plan v3 : docker/init-v3/ ;
  • 🔨 rénover une maison v2 déjà habitée : docker/migrations/v2-vers-v3/, fichiers 03 à 12.

🔍 Le banc (docker/compare_v2_v3.sh) visite les deux maisons et compare tout, pièce par pièce. Aucune différence : les deux chemins mènent au même endroit.

Les mots qui reviennent :

  • contrainte (CHECK, UNIQUE, clé étrangère) : une règle que la base fait respecter seule ;
  • trigger : un petit programme que la base lance à chaque écriture, pour une règle qui regarde d'autres lignes ;
  • test d'intégration : un test qui écrit dans une vraie base de test, fil_rouge_test ;
  • mutant : un piège. On casse exprès une règle, et on vérifie que le test qui la garde échoue. Un test qui ne tombe jamais ne protège rien ;
  • table versionnée : on n'écrase pas un réglage, on en ajoute une nouvelle version datée ; l'ancienne reste pour refaire un vieux calcul ;
  • rôle PostgreSQL : un compte de connexion à la base, avec ses droits (GRANT) ;
  • idempotent : un script qu'on peut relancer sans dégât ; la deuxième fois, il ne trouve plus rien à faire ;
  • pyright : un outil qui relit le Python et cherche les erreurs de type.

❓ Pourquoi : le sujet présente ces chiffres comme des propositions, pas des règles (Q-REM-05). Jeff peut les changer ; sans table, il faudrait modifier le code à chaque fois.

🧩 Ce qui change

🗣️ Jeff, sur Discord : il est d'accord si on l'explique, si ça sert et si c'est cohérent. Le jury fera office de CTO : voici l'explication à défendre.

NiveauNomCe qu'il peut faire

➕ À quoi ça sert

  • Un projet Data-IA lit la base : requêtes d'analyse, notebook, outil de rapport. Sans ce rôle, on leur donne le compte postgres, qui peut tout effacer par erreur.

🧭 Pourquoi deux rôles et pas un

  • L'API se connecte avec postgres : le rôle PostgreSQL ne limite pas un utilisateur de l'API. Il protège les accès directs à la base.
  • Le rôle 'Reader' couvre l'autre porte, celle de l'API. ⚠️ L'API ne vérifie pas encore les rôles : ça viendra avec l'authentification.

🔬 La preuve

F3 · Le format du téléphone

schéma
💬 En clair
Un numéro commence par +, puis 2 à 15 chiffres ; un espace ou un tiret est permis entre deux chiffres. Pris par Claude, seul, à LOT7 : ADR-007 dit « regex E.164 souple » sans la donner.
➕ Le bon côté
Accepte +33 6 12 34 56 78 comme +33612345678 : on tolère la saisie humaine.
➖ Le moins bon
Deux écritures possibles du même numéro : comparer deux numéros demandera de retirer les séparateurs.
🔧 Le détail technique
Le choix
'^\+[1-9]([ -]?[0-9]){1,14}$', sur client, hunter, real_estate_manager.
Écarté
E.164 strict, sans séparateur : plus simple à comparer, plus dur à saisir.
