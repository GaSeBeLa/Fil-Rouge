## 3. Comment les tests sont isolés

**Tests unitaires : aucune base.**
- La base est remplacée par des **objets factices** (`unittest.mock`, bibliothèque standard).
- Pour les routes, `app.dependency_overrides` remplace la session PostgreSQL.
- Le hachage Argon2 (~300 ms par mot de passe) est remplacé par un hacheur faible, le temps du test.

**Tests d'intégration : une base à part, et tout est annulé.**
- **Une autre base** : `fil_rouge_test`, créée par `create_test_db.sh`.
  - Elle rejoue le schéma, la reprise des données et le rôle en lecture seule : **mêmes contraintes** que la base de dev.
  - Pas les 2 556 biens de démo : aucun test n'en a besoin.
- **Tout est annulé** : chaque test tourne dans une transaction, annulée à la fin (rollback).

| Option | Retenue ? | Raison |
| --- | --- | --- |
| Base séparée + annulation | ✅ **oui** | les tests ne dépendent jamais des données de dev |
| Annulation sur la base de dev | ❌ | les tests dépendraient de son contenu |
| SQLite en mémoire | ❌ | ne connaît pas les contraintes PostgreSQL (`CHECK`, `NUMERIC`, `EXCLUDE`) |

## 5. Ce qui n'est pas testé

| Manque | Pourquoi |
| --- | --- |
| « Un seul chasseur est rémunéré pour une vente » | demande plusieurs mandats en base, pas une fonction pure |
| Traçabilité de la rémunération : montant figé, notifications | relève de la persistance, non écrit |
| Calcul en moins de 2 s pour 500 mandats (test de charge) | le calcul est branché sur la base ; le test de charge n'est pas écrit |

Les autres manques du plan initial sont couverts depuis : authentification et droits par rôle, frein aux essais de mot de passe, activation du compte, règles de la base, calcul de rémunération branché sur la base, parcours fonctionnels ([`4.3-tests-fonctionnels.md`](4.3-tests-fonctionnels.md)).

## 6. Rejouer les tests

Depuis `Fil-Rouge-API/docker/` :

```bash
docker compose up -d db api
bash create_test_db.sh
docker compose exec -T api python -m pytest -rs -p no:cacheprovider
```

- `create_test_db.sh` ne sert qu'**une fois**, puis après chaque changement du schéma.
- Sans base : ajouter `-m "not integration"`. Détail de chaque test : ajouter `-v`.
